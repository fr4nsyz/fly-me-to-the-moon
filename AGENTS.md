# Project instructions

Start with `docs/repo-map.md`. It is a generated map of every tracked file and what it is for, so you can find the right file without reading the whole repository. For the reasoning behind a past decision, read the commit log.

The code is the source of truth for what exists. There is no separate spec, state file, or decision log to keep in sync; record decisions in the commit message.

The repository layout is not written by hand. `docs/repo-map.md` is generated by `tools/gen_repo_map.py`; never edit it directly, run the generator instead. `python tools/check_docs.py` fails if a doc points at a path that is gone or if the map is stale, so run it before you finish.

## Implementation workflow

- Suggest first: For any code, file creation, or edits, I'll show you proposed diffs or full code blocks with a brief explanation of what and why.
- No silent writes: I will not apply changes until you explicitly approve them.
- Approval required: Reply with "approve", "yes", an edited version, or questions. I'll only apply after that.
- Keep it transparent: If multiple files are involved, I'll lay them all out clearly for you to review.
